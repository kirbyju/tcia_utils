# Extending the v4 client after T04

Feature modules should define small mixins whose methods call the composition root's shared helpers. T09 wires the mixins into `TCIAClient`. Feature owners do not edit `client.py`, `__init__.py`, or package metadata. Use the accepted [API contract](api-contract.md) and [endpoint matrix](endpoint-matrix.json) for public names, route methods, limits, capabilities, and response shapes.

`self._page(method, path, item_key, *, params=None, json_body=None, limit, cursor=None, max_limit, capability=None)` sends one read request and returns `Page`. Supply exactly one of `params` or `json_body`, excluding `limit` and `cursor`; the helper adds them unchanged to every request. A POST is allowed only for `/v2/.../search`. The helper validates the page envelope and count, retains all original server fields in `Page.response`, and binds `next_page()` to the original filters and observed release. `Page.iter_pages()` is lazy and one-shot: do not call `next_page()` twice on the same cursor. Records remain dictionaries with original service field names. Use `Page.response` for route-specific notes, identity scope, and caveats. A cursor page with more results is partial; a terminal page of an unchanged iteration is complete.

`self._result(method, path, *, params=None, json_body=None, capability=None, required_fields={...}, note_keys=(), bounded=True)` returns the complete named JSON response in `Result.data`. Every feature method must list required top-level response fields and their Python types; missing or mistyped fields raise `ProtocolError`. `note_keys` copies string or string-list notes to `Result.notes` without removing them from `data`. Use `bounded=True` for routes without a cursor, even when `count < limit`; their completeness remains unknown. Only use `bounded=False` for a response that is genuinely complete at its promised scope. Do not infer completeness from `coverage_complete`, which describes participant linking only.

Both helpers observe `/v2/ready` and `/v2/bundle` before the data call and require the named optional capability when provided. A following cursor request also observes identity before and after its data call. `Result.provenance` and `Page.provenance` retain the observed base URL, fingerprint, release tag, profile, capability flags, and observation time. These are request-level observations; records are not individually stamped. Capability false or absent raises `ServiceUnavailableError`, never an empty result. The transport retries only idempotent reads after network failure or a retryable server 5xx, with at most two retries by default. It never retries a 4xx.

Keep path identifiers in one URL segment using `urllib.parse.quote(value, safe="")`; the DOI route preserves its slash using `safe="/"`. Set accepted route-specific maximum limits before calling `_page` and reject out-of-range bounded limits in the feature method. The core import includes only `httpx`; `Result.to_dataframe(key=...)` and `Page.to_dataframe()` import pandas when called and require the `tables` extra. The `examples` extra contains `pandas`, `idc-index`, and `nbformat` for notebooks.

The page helper also accepts `required_fields` and `validate_response(body)` for route-specific evidence and identity checks. Both run on every fetched cursor page, including later pages. Dataset, citation, publication, and download methods require their named scope/provenance fields; participant asset pages verify the requested participant key.
