# Selection and export contract for T08

`_selection.select(records, *, release_identity, query_scope, coverage=None, include_source_images=False)` captures explicit JSON-like records and their observed release provenance. It accepts T04's frozen `Provenance` dataclass or a mapping. `_selection.export_selection(selection, destination, *, overwrite=False)` writes only to the specified directory and returns paths and disposition counts. T09 owns wiring these as flat `TCIAClient` methods; neither function queries the service, calls `idc-index`, runs Data Retriever, reads credentials, or transfers payloads.

The input records need `(dataset_type, short_title)` and a definite `access_level` (`open`/`public` or `controlled`). Ambiguous identity or mixed/unknown row access goes to `unresolved`. Each input index appears once in `selection.json` as exported, deduplicated, excluded, or unresolved, with a reason and safe full captured record so unresolved evidence can be recovered. The companion retains query/filter scope, observed release fingerprint/tag/profile, public HTTPS service origin when present, coverage and caller-supplied completeness, dataset DOI/license/access context, known size totals, unknown size count, and accounting. Local/private service origins are omitted. Credential-bearing inputs, signed URL parameters, private service URLs, and private filesystem paths in records or query scope are rejected before writing. The same captured selection and options produce the same bytes without a new timestamp or network observation. Missing completeness defaults to `unknown`; this module never infers `complete` from a short page or bounded response. A caller asserting `complete` must supply `completeness_basis="terminal_cursor_guarded"` or `"explicit_source_complete"`; the companion labels that claim as caller supplied.

Route evidence is exact and explicit:

| Selection row | Required fields | Output |
| --- | --- | --- |
| Public series | `route_kind="SeriesInstanceUID"`, `record_grain="series"`, exact `series_instance_uid`, `identifier_source="idc-index"` or `"reviewed"`; a raw IDC `SeriesInstanceUID` field is normalized when that source is explicit | `public-series.csv` with only `SeriesInstanceUID` column |
| Public URL | `route_kind="imageUrl"`, exact `imageUrl` with HTTPS and no query/fragment | `public-image-url.csv` with only `imageUrl` column |
| Controlled metadata file | `route_system="ctdc"` or `"general_commons"`, exact `drs_uri` | Separate `controlled-<route>-drs-uri.csv` with only `drs_uri` column |
| Open Aspera package path | exact HTTPS `package_url` and `package_path`, `route_kind="aspera"` or `route_system="aspera"` | Unresolved as `external_application_required`; use the separate metadata-only cohort export described below |

The CSV headers match the Data Retriever's recognized routes in `core/app/spreadsheets.go` and `core/app/run.go`. The exporter emits exactly one route header per manifest. It deliberately excludes `file_id`, `access`, and other fields that the spreadsheet decoder could recognize as an alternate DRS route and override. Duplicate exact identifiers are exported once per manifest, even if they occur in multiple datasets; every dataset association survives in companion accounting. Public and controlled selections never share a manifest. For controlled data, a DRS URI is public inventory metadata, not retrieval authorization. For exact public Aspera files, `TCIAClient.export_aspera_manifest()` queries participant identity, public file inventory and current published download plans, then writes `packageUrl,packagePath` CSV rows. It uses the Participant Explorer convention and requires no Aspera installation. It is not a Data Retriever manifest; the separate Aspera notebook owns invocation of the external application.


For public participant image discovery and direct Python transfers, use `plan_participant_images()` and `download_images()`. The shared metadata service validates dataset-scoped identity and resolves DICOM using the upstream provider. Advanced provider-specific work belongs in the provider's own notebooks and tools. Do not parse opaque asset IDs or detail pointers into transfer identifiers.

The selection input fixture and golden outputs under `tests/fixtures/v4/selection_expected/` are wholly synthetic. Tests parse CSV with the consumer's exact header rules, verify leading-zero UID fidelity, mixed access partitioning, accounting, deterministic bytes, overwrite protection, secret rejection, and absent-route behavior. `selection.json` is a companion schema version 1; changes to its fields or route filenames require coordinated T09/T10 review.
